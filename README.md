# 高校学生通知管理工具

## Flet 桌面窗口

在项目目录使用已有虚拟环境启动（已验证 Flet / flet-desktop 1.1.2）：

```powershell
.\.venv\Scripts\python.exe gui.py
```

窗口支持粘贴正文或选择截图，填写通知发布日期后点击“识别正文”或“识别截图”。
识别结果逐条展示，可修改事项、时间、分类、地点、方式及已识别的参与条件等字段。
确认全部保存前不会写入文件；修改原文或发布日期后需要重新识别。
OCR 在后台运行，失败后可以修改正文重新识别。原始文字及识别依据保留在记录中。

默认写入程序目录的 `todo_list.json`，也可指定独立文件试用：

```powershell
.\.venv\Scripts\python.exe gui.py --file data/gui_trial.json
```

保存后按钮禁用，防止同一批结果重复点击保存；重新导入相同通知仍会新增，不做语义去重。
此窗口当前用于单个桌面进程，勿与命令行或其他窗口同时写入同一 JSON。
提醒仍仅生成计划，不自动推送；本版暂未提供历史待办管理。
首次启动桌面端可能需要下载 Flet 客户端，截图 OCR 首次运行也可能下载模型。


## 转发通知的共同主题与日期编号

“转发自辅导员”等包装文字会跳过，真正标题中的“大学生创新创业训练计划项目申报”保留为共同主题，归竞赛科研。对于 `1. 3月30日前：……`，日期是本编号的时间条件，不是事项名称。可生成“大学生创新创业训练计划项目申报—组建团队与选题/系统填报/提交申报书初稿审核/系统终稿提交/提交纸质材料”等动作名称。

共同主题保存为 `notice_subject`，编号安排的期限可供该编号内动作使用并标记 `stage_heading`；同一动作自己的时间仍优先。通知里仅有一个系统网址时，后文明确提到“系统”的动作可复用该网址，纸质材料仍独立保存送交地点。日期边界按既定“某日前不含当日”规则处理。

## 手动时间输入支持省略分钟

编辑开始、截止或结束时间时，可输入 `2026-11-17 14`，自动保存为 `2026-11-17 14:00`；`2026-11-17 9` 保存为 `2026-11-17 09:00`。日期加完整时分也继续支持，全角冒号可自动转换。只输入日期 `2026-11-17` 时不补造时刻。单独输入 `14` 没有日期，仍需补全日期；非法日期、25点、60分钟等会被拒绝。

## 短通知：事项名称不照抄整句

如“体测补测：下周二下午2点，田径场。没过的同学必须来，过的不用来。”，事项名仅为“体测补测”；时间、田径场、未通过者须参加、已通过者无需参加分别保存。体测/补测归课程学业。新模块 `task_names.py` 负责简短主题命名及独立地点识别，主题无法可靠识别时留待用户填写。

预览可分别编辑参加条件和无需参加人群。相对日期默认按当前北京时间日期换算，保留参考日期与原文时间表达；可用 `--reference-date` 指定通知发布时间。例如参考日期2026-11-10时“下周二下午2点”为2026-11-17 14:00。

## 口语群消息测试

新增 `colloquial.py` 识别无编号群消息的相对日期与多动作。以截图示例，可分别提取“实习证明照片微信提交”“实习证明纸质版送交经管楼507”“实习分享会群接龙”，保留未交材料、自愿参加等条件，不混用地址和参与方式。

“明天、本周五、下周三”等默认以当前北京时间日期换算。处理旧通知时应指定原发布时间。例如假设通知发布于2026-11-11（周三），先运行：

```powershell
.\.venv\Scripts\python.exe main.py --file test_todo_list.json add --reference-date 2026-11-11
```

再粘贴通知，单独输入 `END`。处理旧通知请将日期替换为真实发布时间，也可使用同义参数 `--notice-date`。不指定时自动使用当前北京时间日期，预览同时显示参考日期、原文时间安排和换算结果；也可在预览中手动修改具体时间。

支持常见“下午两点、中午12点”等表达。若“明天（周四）”与参考日期冲突，会提示核对并暂停该消息的相对日期提醒。注意“周五之前”沿用此前不包含周五的约定；只有“周五17:00前”才保留周五17:00。

## 通用阶段与动作拆分规则

阶段解析现已支持不同类型通知，以及“一、信息核对：正文”这种同一行写法。采用“阶段 → 动作 → 本动作的时间/条件/方式/地点”的顺序，不再限定论文通知。完整规则、时间绑定优先级、毕业去向6事项样例和已知边界见 [EXTRACTION_RULES.md](EXTRACTION_RULES.md)。

同阶段的电子上传和纸质提交保留为同组的两个动作，分别记录平台与地址。前一动作明确上传材料及截止，且同句紧接“纸质版交至……”等省略对象的并列渠道时，推定共用截止并标注“沿用同组材料期限，待核对”。推定不是原文独立明示；可单独修改，修改不影响另一动作。跨句/跨阶段、补交、另行通知等不自动沿用。分类补充毕业去向、去向登记、去向落实、档案转递、调档函为就业实习类关键词。

## 多阶段多动作：论文盲审、答辩、材料归档

`stages.py` 对编号章节先分阶段，再按动作拆分；以下论文通知是通用阶段规则的一个样例，可生成5项：

| 阶段 | 事项 | 时间语义 | 平台或地点 |
| --- | --- | --- | --- |
| 论文盲审 | 上传终稿PDF | 3月30日前，按既定边界规则最晚3月29日 | 研究生管理系统 |
| 论文盲审 | 关注结果公布 | 预计4月15日前后，不是确定截止日期 | 未提及 |
| 答辩安排 | 参加答辩 | 4月20日至30日的日期范围 | 具体时间地点由导师另行通知 |
| 材料归档 | 提交纸质论文 | 答辩通过后3个工作日内 | 学院教务办公室（理科楼A201） |
| 材料归档 | 上传电子版论文 | 答辩通过后3个工作日内 | 图书馆学位论文系统 |

保留导师审核通过、通过盲审等前置条件，以及PDF大小、命名格式、论文数量等办理要求。所有事项仍先全量预览，可选事项编号逐项编辑，最后统一保存。标题中的“2025届”仅指届别，无明确年份时使用参考年份并要求人工核对。

新增 `stage`（阶段）、`time_kind`（deadline/range/approximate/relative）、`time_expression`（原文时间安排）、`prerequisite`（前置条件）、`requirements`（办理要求）等字段。条件期限另保留 `depends_on_event` 和 `relative_offset`，例如触发事件“答辩通过”、偏移值3、单位“工作日”、关系“within_after”。

“4月15日前后/左右”不会当作精确截止；“答辩通过后3个工作日内”在实际通过日期未知时保存为待确认，不从计划答辩结束日推算，也不把工作日简单当成自然日。此类记录不生成确定日期提醒。实际日期确认后，可在编辑菜单第2项手动填写具体提醒时间，并保留原文安排供核对；当前不提供工作日日历自动计算或条件自动触发功能。

此阶段解析支持不同主题的编号流程，标题与正文可同一行或分行。缺少编号、同一章节混合多种未知动作、复杂条件引用仍需人工核对；未能可靠拆分的章节会保留整段供确认，不应视为已理解全部语义。

## 维修通知：日期窗口、每日时段与报修渠道

支持维修/报修/保修/检修通知中的完整日期范围、同月省略写法（如“4月1日至5日”）和单日时间段。根据用户提供的原文：

```text
【后勤集团】关于学生宿舍空调维修的通知
3月18日至3月22日每天9:00-17:00，后勤维修组将在各宿舍楼值班，接受空调报修登记。同学可前往本楼宿管阿姨处登记，或拨打报修热线：010-87654321。紧急故障可随时联系。
```

会提取维修开始3月18日、维修结束3月22日、每日服务时段9:00–17:00、地点“各宿舍楼”，以及“本楼宿管阿姨处登记；报修热线：010-87654321”。补充说明保留“紧急故障可随时联系”，不推断为24小时服务。未写号码的热线会标注“号码未提及”；宿管登记点不会自动作为维修地点。

沿用 `deadline` 保存窗口开始，`end_time` 保存窗口结束，`time_role` 标为“维修开始”或“报修受理开始”；`end_time_label` 指定结束时间的显示名称。`service_hours` 单独保存每日时段，`service_note` 保存紧急联系等补充说明，`time_range_expression` 保留原文范围。

预览菜单第6项修改结束时间、第7项修改每日时段（有该信息时显示）、第8项修改补充说明（两项信息都存在时显示）；实际以界面编号为准。原文时间范围作为核对依据保留，不随人工编辑改写。列表按日期窗口显示“待开始/进行中/已结束”，该状态不代表当前正在每日服务时段内。

提醒按窗口开始计算，每日时段不会生成每天重复提醒。对开始时间的两小时提醒会显示“开始前2小时”；缺少具体开始时刻时仍跳过该提醒并提示。当前不自动合并多个维修窗口或解析复杂分段值班表，请人工核对。

## 就业宣讲：现场到场与网申通道分别处理

当就业/招聘/宣讲通知同时提供活动时间和网申通道时，拆成两个独立事项，不把网申截止当成活动时间，也不把网申当成现场报名的必经步骤：

| 事项 | 时间角色 | 方式 | 地点 |
| --- | --- | --- | --- |
| 现场参加宣讲会 | 活动开始、活动结束（例如3月22日19:00–21:00） | 保留“无需报名，直接到场”等原文及现场纸质简历说明 | 活动地点 |
| 网申 | 网申截止（例如4月15日） | 仅网申网址 | 未提及 |

支持 `时间/活动时间/宣讲时间/招聘时间`、`地点/活动地点/宣讲地点`、`参与方式/参加方式`、`网申通道/网申地址/网申链接`、`网申截止/网申截止时间` 等明确标签。网申网址后的“（截止4月15日）”作为时间信息解析，不属于网址本身。没有写网申截止时保留“未提及”，不会借用活动时间。

预览中现场条目标为“参与方式”，网申条目标为“申请方式”，都可以通过第3项修改。新增 `method_role` 保存这个展示标签。就业实习类提醒分别以活动开始与网申截止计算，结束时间仍可通过第6项修改。所有事项先全量预览，最后统一保存。

“2025届”表示毕业届别，不作为活动年份；明确写“2025年”才作为年份线索。没有明确年份时使用参考年份，需要人工核对，或运行时提供 `--reference-date`。此规则面向有明确标签的单场活动与独立网申，不自动判断需要先网申才能入场的复杂条件，请保留并核对参与方式原文。

## 日期边界：“某日前”不包含当日

按本工具约定，“4月1日前”“4月1日（周一）前”“4月1日之前”不含4月1日：保存的 `deadline` 为3月31日，界面标为“最晚提交日期”，同时显示原文和边界解释。括号中的星期不影响识别，也不用于反推年份。没有明确年份时请核对参考年份。

“截至4月1日”“截止时间：4月1日”“即日起至4月1日”仍保留4月1日；“4月1日17:00前”仍保留4月1日17:00。日期型“前”的处理会正确跨月、跨年和处理闰日，不虚构23:59等具体时刻。自然语言有歧义时，以发布方说明及人工修改为准。

新增 `deadline_expression` 保存时间表达，`deadline_boundary="exclusive_date"` 标记不含原日期，`deadline_note` 保存解释。提醒基于实际最晚提交日期计算，例如行政事务的最晚日期为3月31日，则提前3天为3月28日；缺少时刻仍不生成截止前2小时提醒。手动修改时间后按用户输入保存，不再自动减一天。

## 报名截止与活动时间分开识别

对同时包含“报名时间/报名截止”和“活动时间”标签的通知，分别生成报名、参加活动两条事项：

| 时间或信息标签 | 归属与规则 |
| --- | --- |
| 报名时间：即日起至3月20日 | 报名事项的截止日期；不虚构具体时刻 |
| 报名时间：3月10日至3月20日 | 取区间最后一个日期作为报名截止 |
| 报名方式 | 仅用于报名；保留问卷、二维码、现场报名等具体说明 |
| 报名地点／报名方式中的现场地址 | 报名事项的地点 |
| 活动地点 | 参加活动事项的地点 |
| 活动时间：3月28日14:00–18:00 | 开始为3月28日14:00，结束为同日18:00 |
| 服务时长录入第二课堂系统 | 不作为上述报名的提交方式 |

日期缺少年份时仍按标题/学期/参考年份推断。此规则支持明确标签，标签之间可以换行，也可写在同一行；当前每种标签只保留一个值。没有标签的自由叙述、多场活动混排、重复标签等仍需人工核对，不保证自动拆分。

新增 `time_role`（“报名截止”或“活动开始”）标明时间语义；为兼容原结构，`deadline` 存放本条事项用于提醒的时间：报名条目为截止，活动条目为开始。活动额外保存 `end_time`，预览、列表均展示，编辑菜单增加第 `6` 项修改活动结束时间。提醒以报名截止/活动开始计算，不以活动结束计算。

例如活动实践类报名截止3月20日、活动开始3月28日14:00，分别生成3月19日和3月27日14:00的提醒。跨日活动必须在原文写明结束日期，不推测夜间跨日；结束早于开始时会提示核对。

## 一份通知包含多个提交事项

新版 CLI 使用 `extract_notices()` 返回事项列表。一份通知含多个带独立截止时间的提交/报名/缴费等动作，且语句边界能够区分时，会分别生成待办。例如：

```text
【团委】关于举办2025年“挑战杯”院级选拔赛的通知
参赛团队请于3月25日17:00前将申报书（PDF版）发送至邮箱 xiaoming@school.edu.cn。
纸质版材料一式三份于3月26日12:00前交至文科楼302办公室王老师处。
```

预期生成：

| 事项 | 截止时间 | 提交方式 | 地点 |
| --- | --- | --- | --- |
| 挑战杯院赛—申报书电子版提交 | 2025-03-25 17:00 | 邮箱及具体邮箱地址 | 未提及 |
| 挑战杯院赛—纸质材料提交 | 2025-03-26 12:00 | 纸质版 | 文科楼302办公室 |

先展示全部事项及各自的时间、提交方式、地点、分类、提醒计划。输入事项编号进入该项的编辑预览，再输入内容编号修改；确认修改后返回多事项总览。总览输入 `y` 才一次性保存全部事项；输入 `n` 或中途按 Ctrl+C 不会保存其中一部分。

每项的 `source_text` 保留完整通知，`source_segment` 保留对应语句。方法和地点从对应语句提取，避免把线上邮箱和线下地址混用。通知主题与分类继承自完整通知，仍可人工修改。

同一报名的开始时间与截止时间仍保留一项，截止时间优先。当前自动拆分支持明确标签的报名/活动阶段，以及有分句边界、有明确动作的多截止事项；其它复杂时间范围、仅两个开始时间、跨段引用和缺失日期的动作暂不能可靠拆分，需人工拆成多次输入。单条提取接口 `extract_notice()` 仍保留以兼容已有调用。

## 新版：事项分类与差异化提醒计划

识别后先完整展示事项、时间、提交方式、地点、分类和提醒计划。只选择有误的内容修改，全部正确时直接输入 `y` 保存，无需逐项回车。

## 预览核对与按需修改

```text
========== 提取结果预览 ==========
1. 事项名称：挑战杯申报书提交
2. 截止/事件时间：2026-12-10 17:00
3. 提交方式：邮箱 xiaoming@school.edu.cn
4. 事件地点：文科楼302办公室
5. 分类标签：竞赛科研

提醒计划：
  提前5天：2026-12-05 17:00
  提前1天：2026-12-09 17:00

原文来源：已折叠（输入 v 展开查看）
输入 1–5 修改对应内容 / v 展开或收起原文 / y 全部确认保存 / n 放弃：
```

- 输入 `1` 至 `5`，只编辑对应内容，修改后自动返回完整预览。
- 编辑时回车保留原内容；输入新内容替换；输入“未提及”清空普通内容。分类选择编号或名称，兜底类别为“其它类别”。
- 时间支持 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM`，不合法会要求重新输入。时间或分类变化后提醒计划立即更新。
- 输入 `v` 展开/收起原文及自动分类依据，原文默认折叠。
- 输入 `y` 全部确认保存，`n` 放弃；主菜单直接回车不会保存。Ctrl+C 或输入中断也不会新增记录。
- 信息缺失、只有日期没有时刻、时间格式异常、分类不明确或多类命中会有“待核对”提示。这些是规则检查提示，不是 OCR 置信度评分，也不会强制阻止人工确认。

当前为命令行交互，编号选择对应预览中的项目；此版本没有鼠标点击或双击编辑功能。

| 关键词（任一命中） | 分类 | 提醒策略 |
| --- | --- | --- |
| 选课、考试、成绩、补考、调停课、体测、补测 | 课程学业 | 提前3天、截止前2小时（活动按开始时间） |
| 挑战杯、大创、创新创业训练计划、竞赛、论文、讲座 | 竞赛科研 | 提前5天、提前1天 |
| 社团、志愿、实践、文化节、招新 | 活动实践 | 提前1天 |
| 宣讲、招聘、实习、简历、就业、毕业去向、去向登记、去向落实、档案转递、调档函 | 就业实习 | 提前7天、提前1天 |
| 奖学金、助学金、学籍、宿舍、证明、住宿/入住/退宿/调宿申请 | 行政事务 | 提前3天、截止前2小时 |
| 医保、体检、图书馆、校园卡、食堂、维修、报修、保修、检修 | 生活服务 | 提前1天 |

分类规则位于 `categories.py`，提醒逻辑位于 `reminders.py`。第 7 项为“其它类别”，无命中时使用该分类。优先判断主事项动作：宿舍申请/分配/调换等归行政事务，维修/报修/保修/检修归生活服务，避免“宿舍”地点词覆盖维修事项。其它情况中，事项名仅命中一个分类时优先该类；否则按全文命中的不同关键词数量选择，平局则保留“其它类别”。界面展示关键词依据及多类命中提示，最终以用户确认的分类为准。该规则是关键词匹配，无法解决 OCR 错字、否定表达或所有复杂语义。

提醒相对确认后的 `deadline` 计算，保存在 `reminder_times` 中。“其它类别”提醒策略为提前1天和截止前2小时。提前 N 天保持相同时刻；只有日期时生成日期级计划，不擅自补时刻。课程学业、行政事务和其它类别缺少时刻时跳过“截止前2小时”并给出说明。时间未确定时不生成计划。

使用以下命令查看某一分类和全部提醒计划：

```powershell
.\.venv\Scripts\python.exe main.py --file test_todo_list.json list --category "课程学业"
.\.venv\Scripts\python.exe main.py --file test_todo_list.json reminders
```

`reminders` 仅按时间排序输出全部计划，包含过去的计划，不会自动弹窗、发送消息或执行去重。修改分类或时间后计划会重新计算。旧版 JSON 可直接读取，缺少分类或分类为旧名称“未分类”的历史记录在内存中显示“其它类别”；读取不会改写旧文件，后续新增保存时会补齐结构并使用新名称。

新增 JSON 字段示例：

```json
{
  "category": "行政事务",
  "category_candidates": ["行政事务"],
  "category_matches": {"行政事务": ["奖学金"]},
  "reminder_times": [
    {"label": "提前3天", "time": "2026-12-07 18:00"},
    {"label": "截止前2小时", "time": "2026-12-10 16:00"}
  ],
  "reminder_note": ""
}
```

`category_candidates` 和 `category_matches` 保留自动分类依据，人工调整分类后也保留该依据用于核对。新版没有新增第三方依赖。

Python 3.10+ 命令行程序。文本模式只用标准库，无须安装第三方依赖。所有通知经过人工确认后才写入 JSON；截图 OCR 统一使用 PaddleOCR 3.x。

## 快速运行

先进入程序目录，以下命令均在此目录执行：

```powershell
cd D:\working\gpt\student_notice

```

预期提取结果：

```json
{
  "task": "选课补退选",
  "deadline": "2025-03-12 12:00",
  "submit_method": "教务系统",
  "location": "未提及",
  "source_text": "【教务处通知】2024-2025-2 学期选课补退选将于 3 月 12 日 12:00 结束，请未确认的同学登录教务系统完成操作，逾期不再受理。"
}
```

识别后一次展示所有提取项。输入 `1` 修改事项、`2` 修改时间、`3` 修改提交方式、`4` 修改地点、`5` 修改分类。无需输入字段名，也无需依次确认正确的内容。

修改后自动返回完整预览，可继续选择其它项目修改；输入 `y` 确认保存、`n` 取消。只有最终确认才写入 JSON。原始 OCR 文字保留，可输入 `v` 查看；修改的是提取后的内容。此功能用于新增记录保存前，不会修改已保存记录。

时间规则会排除带“发布时间、发送时间、更新日期、落款”等标记的日期。缺乏明确事件语义的日期（例如独立聊天时间戳）不再自动作为事件时间，而是显示“未提及”，请手动确认。复杂排版或 OCR 漏字仍可能影响判断。

也可多行粘贴：

```powershell
python main.py add
```

粘贴后另起一行输入 `END`（也支持小写 `end`）。Ctrl+C 或输入中断会取消新增。

默认保存到**当前工作目录**的 `todo_list.json`，格式为对象数组，新增时追加记录。

指定文件、查看待办和查看未来七天及全部逾期事项：

```powershell
python main.py --file data/todo_list.json add --text "奖学金申请截止2026年12月1日18:00，请登录学生服务平台提交。"
python main.py list
python main.py list --days 7
python main.py --help
```

`--file` 放在子命令前。列表按时间排序；无时间的记录排在最后。`--days` 筛选排除无时间记录。列表仅展示，不会自动弹窗或发送消息。目前不提供完成状态管理和去重，每次确认都会新增一条。

## 提取规则与边界

- 识别中文和常见数字日期，例如 `2025年3月12日12:00`、`2025-03-12 12:00`、`3 月 12 日下午3点`；截止/结束优先于开始/举行时间。
- 缺少年份时，优先从 `2024-2025-2 学期` 推断第二学期为 2025 年，第一学期为 2024 年；其次参考标题中的独立活动年份（如“2025年挑战杯”）；否则使用当前年份或 `--reference-date 2025-01-01` 指定的参考年份。跨年、标题年份与实际截止年份不同、特殊校历请人工修正。
- 只有日期时保存 `YYYY-MM-DD`，不虚构具体时刻；列表将该日期的当天结束视作逾期分界。有时刻时保存 `YYYY-MM-DD HH:MM`。均使用本机当地时间。
- 通用解析的同级时间候选取文本中首项；报名区间取末日，活动标签可解析开始/结束时间。口语消息中的“明天”“下周五”等需指定通知发布时间，详见上文。无法确定的时间为“未提及”。暂不识别农历、只有时刻的通知和无明确标签的复杂跨日时间段。
- 事项优先显式标题，然后常见事项关键词，再从首句截取，最长 40 字。方法匹配平台、邮箱、网址、纸质和接龙等关键词；地点优先匹配“地点/地址”字段。
- 规则无法保证理解所有自然语言，提取结果必须人工确认；缺失字段为“未提及”。明确的多截止提交事项可自动拆分，复杂通知仍需人工拆分输入。
- JSON 使用临时文件原子替换；已有文件损坏会报错并保留原文件。当前仅支持单进程写入，不要让多个实例同时新增。

## 扩展定时提醒

目前提供按时间筛选的待办输出，可让定时任务每天调用列表命令。

Windows：在“任务计划程序”中新建每天触发的任务；程序填写 Python 可执行文件的绝对路径，参数填写 `"D:\working\gpt\student_notice\main.py" --file "D:\working\gpt\student_notice\todo_list.json" list --days 7`。计划任务的控制台输出不等于桌面通知，需要另加通知模块或输出日志。

Linux/macOS 的 cron 示例（路径须替换为实际绝对路径）：

```cron
0 8 * * * /usr/bin/python3 /path/student_notice/main.py --file /path/student_notice/todo_list.json list --days 7 >> /path/student_notice/reminders.log 2>&1
```

后续可在 `show_todos()` 的筛选逻辑上增加桌面通知、邮件提醒，并在数据结构中加入 `id`、`completed`、`last_reminded_at`，避免已完成任务和重复提醒。若要支持并发写入，建议迁移到 SQLite。
# 起止时间提醒

同一事项有明确开始与结束时间时，提醒策略优先采用：开始前1天、开始时、截止前2小时。只有单点时间的事项继续使用分类默认策略。

例如选课从2025-03-15 12:00开始，至2025-03-18 18:00结束，将生成2025-03-14 12:00、2025-03-15 12:00、2025-03-18 16:00三个提醒。预览可修改开始或截止时间，确认后重新计算并保存。没有具体时刻时不会补零点，截止前2小时提醒暂不生成。程序目前输出提醒计划，不自动发送通知。
